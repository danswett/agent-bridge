# Optional background alerts for iPhone and iPad

The default local build keeps its foreground notification behavior and requires no push provider. This proposal adds a sandbox push variant for a host and client that both advertise native notifications. An entitlement alone does not enable remote alerts.

**Enrollment.** On an already authenticated device, offer a separate “Notify me while closed” switch only when the relay advertises an APNs provider for the signed app's topic and environment. Request notification authorization in response to that switch, then register with APNs. Send the returned token over the authenticated relay using the proven device identity. Upsert the registration on every registration callback. Store a random registration ID bound to the account, device public key, topic and environment. Encrypt tokens at rest; exclude tokens, session titles and paths from logs. Isolate native tokens from the Web Push subscription store.

**Delivery.** An authenticated host publishes a generic wake alert for a recipient registered to the same account. Enforce recipient scope, quotas, TTL and collapse ID before contacting APNs. Use an alert push with only “A session needs your attention”; leave agent text, IDs, prompts and attachments off the lock screen. On tap, open the client, unlock if needed, reconnect and fetch current authorized sessions. Foreground notifications continue to use the existing event planner. Suppress the duplicate when a foreground session is already focused. The provider signing credential belongs in the relay secret store, never the app.

**Revocation.** Switching off, signing out, removing a device, or losing notification authorization invalidates the registration. Offline sign-out clears local state immediately; the server must support independent account-side revocation. Ignore stale events, remove registrations after a permanent APNs rejection, and retry transient failures with bounded backoff until expiry. A new token or environment supersedes the previous binding.

**Signing and acceptance.** Enable Push Notifications on the explicit app identifier, provision its development profile and run `DEVELOPMENT_TEAM=<team> apple/scripts/build-ios-push-development.sh`. The helper verifies the application signature and both sandbox entitlements. It only selects the entitlement for that build. Use a sandbox provider, a disposable recipient and a locked physical iPad to verify delivery, revocation, absence of private payloads and foreground deduplication. The normal local client continues to build without either provider credentials or a push profile.

Apple documents the device registration and provider roles in [Registering your app with APNs](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns) and [Setting up a remote notification server](https://developer.apple.com/documentation/usernotifications/setting-up-a-remote-notification-server).
